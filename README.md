# 自动备货 · 假人执行

Fabric 模组 · 版本 `1.0` · Minecraft `1.21`–`26.2`

自动扫描建筑材料，生成备货任务，并通过 Carpet 假人完成取货、装盒与运输。

## 功能

| 功能 | 说明 |
|---|---|
| 材料扫描 | 扫描 Litematica 材料列表，读取需求、倍率和已绑定区域。 |
| 自动备货 | 从材料区取出物品，按冻结的任务需求整理到空盒区和备货区。 |
| 假人执行 | 通过 Carpet 假人执行运输流程，支持暂停、恢复、取消、召回和删除。 |
| 区域管理 | 分别绑定材料区、空盒区和备货区，并检查区域关系与库存状态。 |
| 任务管理 | 生成、确认、冻结和执行备货任务；执行前会再次复核现场。 |
| HUD | 显示区域、任务、库存和执行状态，支持位置、透明度、文字颜色、强调色和背景颜色设置。 |
| 兼容后端 | 优先使用可用的 QuickShulker 后端；不可用时自动使用直接后端。 |

## 支持版本

项目仅支持 Fabric。表中的同一发行文件可以覆盖对应的整个版本区间：

| Minecraft | 发行文件 |
|---|---|

| 1.21.1 | `autostock-1.21.1-1.0.jar` |
| 1.21.2–1.21.4 | `autostock-1.21.2-1.21.4-1.0.jar` |
| 1.21.5 | `autostock-1.21.5-1.0.jar` |
| 1.21.6–1.21.8 | `autostock-1.21.6-1.21.8-1.0.jar` |
| 1.21.9–1.21.10 | `autostock-1.21.9-1.21.10-1.0.jar` |
| 1.21.11 | `autostock-1.21.11-1.0.jar` |

只能使用与 Minecraft 版本对应的发行文件，不要跨区间安装，也不要把 `sources.jar` 当作模组安装。

## 依赖

请为当前 Minecraft 版本安装对应的 Fabric 版本：

- Fabric Loader
- Fabric API
- Carpet
- Litematica（客户端）
- MaLiLib（客户端）
- QuickShulker（可选）

QuickShulker 是可选依赖。安装并可用时，模组会使用兼容后端；未安装或不可用时使用直接后端。Minecraft `1.21` 使用直接后端。服务端不需要安装 Litematica 或 MaLiLib。

## 安装

1. 安装对应 Minecraft 版本的 Fabric Loader 和 Fabric API。
2. 安装同版本兼容的 Carpet；客户端另外安装 Litematica 和 MaLiLib。
3. 从 Release 下载对应的 `autostock-*-1.0.jar`，放入 `mods` 文件夹。
4. 客户端和服务器使用同一支持区间的发行文件。
5. 删除旧版 AutoStock，避免同一实例加载多个版本。

## 使用

### 1. 绑定区域

使用 Litematica 选择并绑定三类区域：

- 材料区：存放可供取用的建筑材料。
- 空盒区：存放用于装载材料的空盒或容器。
- 备货区：存放完成备货的容器。

绑定后检查区域位置、容器类型和可用空间。

### 2. 创建任务

在 Litematica 材料列表中确认过滤项和倍率，然后打开模组配置的“任务”页生成备货清单。确认需求无误后冻结任务，冻结后的需求不会因实时库存变化而悄悄改变。

### 3. 放置假人并执行

在“假人”页放置或召回假人，确认假人库存和区域权限后启动任务。任务页可以暂停、恢复或取消执行，并查看当前阶段和库存同步状态。

### 4. 调整 HUD

在“显示”页调整 HUD 的位置、透明度、文字颜色、强调色和背景颜色。设置面板会根据 HUD 所在侧避让显示区域，避免遮挡状态信息。

### 5. 删除假人

删除假人前必须清空其背包、末影箱、光标物品和模组保留物品。假人仍持有物品时，模组会拒绝删除并保留现场。

## 权限与限制

- 每位玩家使用一个专用假人。
- 扫描、区域绑定和假人控制需要单人存档所有者身份或服务端权限等级 2。
- 只接受普通建筑方块需求；特殊物品会被拒绝。
- 所有库存与路径数据都是执行前后的服务端快照，执行前会再次复核现场。
- 自动寻路只覆盖已加载区块和普通建筑环境；复杂地形可能需要人工处理。

## 本地构建

项目使用 Stonecutter 管理版本差异，并使用仓库自带的 Gradle Wrapper。GitHub Actions 会构建并验证全部 16 个正式版本，最后收集 9 个不重复的发行文件。

构建单个版本：

```powershell
.\gradlew.bat --no-daemon :26.2:buildAndCollect
```

构建结果位于 `build/releases/`。发布工作流必须由维护者手动确认，不会因普通推送自动发布 Release。
